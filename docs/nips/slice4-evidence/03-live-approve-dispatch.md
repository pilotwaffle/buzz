## BLOCKER found live — outcome event rejected by the relay (settlement never completes)
When goose tried to publish its delegation outcome event (kind 9, threaded per spec 4.4: root=origin, parent=wake), the relay REJECTED it:
  POST /events -> 400  reason="invalid: root tag does not match thread ancestry"  (twice, 15:58:24 and 15:58:27; sidecar: "delegation outcome post failed: HTTP error: POST /events returned HTTP 400 Bad Request")
Consequently delegation_actions.settled_at and .outcome remain NULL — the delegation never settles; in production it would be swept as a timeout and strike, even on a real answer/breach.

Root cause (to route): the sidecar builds the outcome event threaded under the ORIGIN event (root=origin, parent=wake), but the relay's kind-9 thread-ancestry validator requires the root tag to match the message's actual thread ancestry, and the wake event is not an ancestor under the origin in the way that check expects. The automated e2e suite (02-e2e-scratch.md, 7/7) missed this because it posts outcomes through an internal path, not the agent's real POST /events through the relay's kind-9 validator. This is an integration-seam defect only reachable live (rule-10 lesson).

## FINDING F-3 (live, MAJOR-ergonomics) — root delegation block fails to parse: parent_approval_event_id not #[serde(default)]
DelegationRequestDraft (crates/buzz-core/src/delegation.rs) marks `origin_event_id` with #[serde(default, skip_serializing_if)] but `parent_approval_event_id` (Option<String>) and `cost_cap_microusd` (Option<u64>) have NO #[serde(default)]. serde therefore REQUIRES those keys to be present in the JSON. A natural root delegation (no parent, no cost cap) omits them, so approve_delegation's serde_json::from_str fails with "missing field `parent_approval_event_id`", surfaced in the UI as "delegation block failed to parse". Every agent-drafted or hand-written root delegation hits this. Workaround for the gate: include "parent_approval_event_id": null (and "cost_cap_microusd": null). Real fix (route to builder): add #[serde(default)] to both Option fields so they may be omitted, matching origin_event_id — and update base_prompt.md's example accordingly (compounds F-1). Verified live 2026-09-16: block c8d2f3a5...settle000002 was valid JSON, omitted parent_approval_event_id, and the relay never saw it (client-side parse fail).
